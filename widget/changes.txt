OBJECTIVE
════════════════════════════════════════════════════════════

Refactor this project into an installable Python package named dpi-ls so that any
developer can monitor their AI agent's performance across all 7 dimensions by adding
just TWO LINES to their existing agent script — one import and one monitor() call —
regardless of which LLM framework they use.

Supported frameworks to intercept automatically:
  - OpenAI Agents SDK
  - LangGraph
  - LangChain
  - CrewAI
  - AutoGen
  - Raw OpenAI / Anthropic client calls
  - Any other framework (graceful fallback with inferred metrics)

When the user runs their agent script, the package must:
  1. Intercept the agent's runtime calls silently in the background
  2. Collect raw signals for all 7 dimensions throughout execution
  3. Use a LangGraph-based LLM evaluator ONLY for the Quality (Q) dimension
  4. Use deterministic math (no LLM) for the other 6 dimensions: P, E, G, R, V, C
  5. Auto-start the FastAPI dashboard server at localhost:8000 in the background
  6. POST a canonical AgentObservation to /ingest after the agent finishes
  7. Keep the dashboard server alive so the user can browse results at localhost:8000

════════════════════════════════════════════════════════════
MEASUREMENT STRATEGY
════════════════════════════════════════════════════════════

P — Productivity  : count(outputs) / baseline_outputs         ← deterministic, NO LLM
Q — Quality       : LangGraph graph with 3 LLM scoring nodes  ← LLM ONLY HERE
E — Execution     : successes / attempts counter              ← deterministic, NO LLM
G — Governance    : regex policy check on outputs             ← deterministic, NO LLM
R — Risk          : error frequency × severity weights        ← deterministic, NO LLM
V — Validation    : JSON schema presence check on outputs     ← deterministic, NO LLM
C — Cost          : token usage × configured price per token  ← deterministic, NO LLM

The 7 scoring formulas (DO NOT change these — engine/ owns the math):
  P = min(1, AI_outputs / human_baseline)
  Q = 0.70 * Accuracy + 0.20 * Consistency + 0.10 * (1 - Hallucination)
  E = successful_executions / attempts
  G = 1 - (policy_violations / total_actions)
  R = 1 - min(1, sum(freq * severity) / R_max)
  V = validated_components / required_components
  C = min(1, human_cost / AI_cost) * utilization

Composite: DPI-LS = 100 * (P^0.15 * Q^0.20 * E^0.15 * G^0.20 * R^0.15 * V^0.10 * C^0.05)

Hard gates: If G < 0.60 OR R < 0.50 OR V < 0.60 → score capped at 69, flagged Unsafe

Bands: 85–100 Exceptional | 70–84 Strong | 50–69 Needs Optimization | <50 Underperforming/Unsafe

════════════════════════════════════════════════════════════
LLM CONFIGURATION — Q DIMENSION EVALUATOR ONLY
════════════════════════════════════════════════════════════

For the LangGraph Quality evaluator, use AWS Bedrock via LangChain:

    from langchain_aws import ChatBedrockConverse
    import os

    llm = ChatBedrockConverse(model_id=os.getenv("MODEL_NAME"))

The user sets MODEL_NAME in their .env file, e.g.:
    MODEL_NAME=us.amazon.nova-pro-v1:0

AWS credentials are resolved automatically from the environment
(AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY / AWS_DEFAULT_REGION)
or from an active IAM role. No extra auth config needed.
